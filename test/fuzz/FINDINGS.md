# Fuzzing Findings

Executed on 2026-10-29 against `npm run dev:local` in headless Chromium (Playwright), with mock responses standing in for text detection, final AI review, and speech-to-text transcription.

## How to run

```sh
npm run dev:local                        # Start the local server in another shell
npm run test:fuzz                        # Run shared-code property tests, then test every corpus file in the browser
node test/fuzz/run.mjs fuzz-out 'pdf$'   # Run a specific subset; writes results to fuzz-out/results.json and screenshots to fuzz-out/shots
```

- `shared.ts` feeds randomized plain text, JSON, JSONL, XML, and subtitle files through the matching (`analyzeUnits`, `findTerms`) and redaction (`redactStructured`, `maskText`, `labelText`, `rewriteSegments`) pipelines. It verifies that redacted JSON remains valid, subtitle cue timings stay intact, XML markup is preserved, and every occurrence of a detected value is masked.
- `corpus.mjs` generates 176 test files (covering valid, edge-case, and malformed inputs across every supported format) plus 90 mutated copies of 15 valid files (truncated files, flipped bits, injected random bytes, and truncated, duplicated, or malformed XML parts inside Office archives). Most files embed the same three canary PII values: `Jane Doe`, `jane@example.com`, and `415-555-0132`.
- `run.mjs` loads each file through its corresponding web UI and walks through the full user flow: opening and previewing the file, clicking Upload, running detection and matching, drawing a manual redaction box on the first page, and exporting the redacted file. It then independently validates the downloaded output: images, PDFs, and audio files are decoded (`sharp`, `pdf-lib`, `ffprobe`), Office files are opened headless in LibreOffice, every XML part and text stream is scanned to confirm none of the three canary values remain, metadata is verified stripped, and unredacted text is checked for preservation. Every file must either open cleanly or be rejected with a clear, human-friendly error message; page hangs, uncaught exceptions, or raw third-party library error strings count as failures.

## Summary of results

No test cases hang or crash the browser tab. Each failure pattern documented below was reproduced by at least one corpus file prior to fixing; after applying the fixes, 262 of 266 files pass completely, with 4 known edge cases listed under [Still open](#still-open).

| Stage | Before fix | After fix |
| --- | --- | --- |
| Open & preview | Raw library error strings shown for damaged PDFs, ZIP archives, and images; arbitrary binary files opened as garbled text | Clear user-facing error messages; binary files rejected |
| Text decoding | Windows-1252 files lost accented characters (`Café` became `Caf`) | Decoded using the file's original character encoding |
| OCR | White text on transparent PNGs produced empty OCR output | Composited onto a dark background before OCR |
| Matching | Names immediately following `\n` or `\t` escape sequences in JSON or source code were missed | Matched accurately |
| Export | Office XML parts rejected by the browser's `DOMParser` were silently skipped and written back unredacted | Normalized and parsed, or the file is rejected up front before review |

## Fixed failure patterns

1. **Unparseable Office XML parts were left unredacted (security issue).** The Word, PowerPoint, and Excel loaders previously skipped any XML part rejected by the browser's `DOMParser` and left the original part untouched in the ZIP archive, allowing unredacted text to slip into the downloaded file unseen. Browsers reject several constructs that desktop Office applications silently accept—most notably XML parts encoded as UTF-16 (when decoded as UTF-8) and characters forbidden by XML 1.0 such as `&#1;`. Triggering fuzz cases: `word-utf16-header.docx` and `word-bad-char-header.docx` (leaked a name in the document header), as well as `deck-*-slide.pptx` and `sheet-*-strings.xlsx`. **Fix:** `readXml` now inspects the byte order mark (BOM) or XML encoding declaration, strips characters forbidden by XML 1.0, and throws a `FileError` if any XML part still fails to parse (`checkParts` validates all XML parts on open so damaged files are rejected before review rather than during download). Serialized XML parts are normalized to UTF-8. This also fixed a leak where malformed `docProps/core.xml` or `meta.xml` files retained the document author's name.
2. **Raw library error messages exposed in the UI.** Malformed files previously surfaced internal exceptions from `pdf.js` (`"No password given"`, `"Invalid PDF structure."`, `"The PDF file is empty, i.e. its size is zero bytes."`), `JSZip` (`"Can't find end of central directory..."`, `"Corrupted zip or bug: unexpected signature..."`), the browser (`"The source image could not be decoded."`), `UTIF.js` (`"Invalid array length"`), and unhandled `TypeError`s from damaged workbooks (`"Cannot read properties of undefined (reading 'richText')"`). **Fix:** Expected validation errors throw `FileError` with clear user-facing copy, while unexpected parser exceptions are caught by `openFailure` and mapped to a friendly format-specific message. Password-protected PDFs now prompt for the password directly below the drop zone (and re-prompt if incorrect), while clicking Cancel cleanly resets the view.
3. **Windows-1252 text files were corrupted on load and export.** Because `File.text()` always decodes as UTF-8, CSVs saved by Excel or Windows Notepad had every accented character replaced with ``. Additionally, stripping the UTF-8 BOM caused Excel to misinterpret re-saved "CSV UTF-8" files. **Fix:** `decodeText` checks for a BOM first, attempts strict UTF-8 decoding, falls back to Windows-1252, and detects BOM-less UTF-16. Downloaded files preserve or add a UTF-8 BOM whenever the original file had a BOM or used a non-UTF-8 encoding.
4. **Binary files opened as plain text.** Arbitrary binary data renamed to `.txt` (or lacking an extension and MIME type) previously opened as garbled text and could be submitted for AI detection. **Fix:** `decodeText` rejects any file containing more than 5% control bytes.
5. **Names immediately following escape sequences were missed.** In strings like `"Hello\nJane Doe"` inside JSON, logs, or source code, whole-word boundary matching treated the `n` in `\n` as a word character attached to `Jane`, preventing `"Jane Doe"` from matching. **Fix:** Letters immediately preceded by a backslash are no longer treated as part of the following word when checking leading word boundaries.
6. **Quoted values inside XML DOCTYPE declarations were skipped.** Declarations such as `<!ENTITY name "Jane Doe">` were treated as structural markup and left unredacted. **Fix:** Quoted literals inside `<!...>` declarations are now treated as redactable segments alongside attribute values.
7. **White text on transparent images was invisible to OCR.** Compositing transparent images onto a white canvas erased white text on transparent backgrounds. **Fix:** `opaque()` in `src/client/formats/ocr.ts` samples pixel luminance and composites predominantly light foreground marks onto a black background before running Tesseract.
8. **Misleading warning message for damaged images in Word and PowerPoint.** Corrupted PNGs embedded in Office documents were previously reported as being in "EMF, WMF or TIFF format." **Fix:** The warning note now accurately states that the embedded image could not be opened and was left unchanged.
9. **ExcelJS preview failures blocked spreadsheet loading.** Because ExcelJS (used only to render the visual spreadsheet grid) is stricter than AnyRedact's own XML spreadsheet reader, certain valid workbooks failed to open altogether. **Fix:** If the visual grid renderer fails, the editor gracefully falls back to the structured cell list view.

## Still open

| Issue | Corpus file | Impact | Possible mitigation |
| --- | --- | --- | --- |
| Very large text in high-resolution photos is missed by Tesseract | `big.jpg` (200 px letters on an 8000×6000 canvas) | 1 of 3 canary values missed by OCR | Run a second OCR pass on a downscaled copy when initial OCR finds sparse text on a large image |
| CMYK TIFF with JPEG compression decodes as visual noise | `cmyk-jpeg.tiff` | Preview is unreadable and OCR finds nothing; exported TIFF contains only noise, so no PII leaks | Decode JPEG-compressed TIFF strips via the browser's image decoder, or reject the file up front |
| SVG without `width`, `height`, or `viewBox` defaults to 300×150 | `no-size.svg` | Content outside the 300×150 viewport is clipped in both preview and PNG export, so no PII leaks | Compute bounding box dimensions from the rendered SVG elements |
| Malformed PDF missing both `xref` table and `trailer` | `no-xref.pdf` | Rejected with a friendly error message, whereas some desktop PDF viewers attempt recovery | Leave as-is |
| Synthetic spans that split a surrogate pair leave half an emoji | `shared.ts` | Only reachable via synthetic byte offsets; AI detection and term matching never split surrogate pairs | Leave as-is |
| `.odt`, `.odp`, `.docm`, and video files are rejected | — | User is prompted to convert to a supported format | Candidate formats for future support |

**Formats passing all fuzz checks:** plain text, structured data, and subtitles (TXT, CSV, TSV, JSON with BOM/comments/5,000-level nesting, XML with billion-laughs protection, HTML, `.env`), PDF (rotated pages, offset MediaBox, 200-inch and 1-inch pages, 61+ pages, scanned pages, character-by-character text runs, rotated text, AcroForm fields, owner-password encryption, user-password unlocking), PNG (16-bit, indexed palette, interlaced, transparent), JPEG (CMYK, progressive, all 8 EXIF orientations), WebP, AVIF, animated GIF and WebP, BMP (24-bit and 1-bit), TIFF (LZW, JPEG, tiled, 16-bit, CMYK, CCITT Fax G4, multi-page), SVG (embedded scripts, external image refs, BOM, oversized dimensions), HEIC, Word DOCX (per-character runs, XML entities, nested tables, text boxes, tabs and hyphens inside PII values, missing and corrupted media, 20,000 paragraphs, LibreOffice output), PowerPoint PPTX (tables, speaker notes, 120 slides, image-only slides, zero-slide decks, LibreOffice output), Excel XLSX (rich text, shared formulas, merged cells, legacy notes, special characters in sheet names, hidden and empty sheets, 100,000 cells, cell at `XFD1048576`, LibreOffice output), OpenDocument ODS, and audio in WAV, MP3 (ID3 tags stripped), M4A, Ogg, Opus, FLAC, and AAC (up to 9 minutes across three transcription chunks).
